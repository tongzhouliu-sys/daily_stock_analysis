> 状态：待实施
> 基线：`main` @ `7190a261`
> 任务类型：`feat`（含 `refactor`，仅展示层）
> 影响面：`apps/dsa-web/src/pages/HomePage.tsx`、`apps/dsa-web/src/components/report/*`、`apps/dsa-web/src/research.css`、`apps/dsa-web/src/locales/*`、`apps/dsa-web/e2e/fixtures/*`、`docs/CHANGELOG.md`

## 1. 背景与问题

### 1.1 现象

手机打开一份已生成的分析报告，第一屏几乎全是操作区和封面头部，**看不到任何结论文字**；要读完一份报告需要滚 4 屏以上，且报告内的次要操作、折叠区、空状态都存在可读性与触控问题。

### 1.2 实测数据（390×844，真实组件 + 固定数据）

| 区域 | 顶部位置 | 高度 | 说明 |
| --- | --- | --- | --- |
| 顶栏 `.research-masthead` | 0 | 64 | sticky |
| 分析命令区 `.research-command-bar` | 88 | **174** | 输入框 + 服务器选择 + 推送 + 大盘复盘 + 分析 |
| 报告头 `.research-panel-heading` | 279 | 48 | 「分析报告 / 研究记录」 |
| 报告工具栏 `.report-toolbar` | 341 | **82** | 3 个次要按钮一行 + 完整报告独占一行 |
| 封面 `.report-hero` | 439 | **646** | 代码/日期/自选/分享/名称/价格/指标带/核心洞察 |
| 指标带 `.report-facts` | 648 | 108 | 2×2 |
| **核心洞察正文** `.report-key-insight` | **773** | 291 | 844 高的手机上首屏只剩最后 70px |

同一份数据下，桌面端受命令区与工具栏占用的影响更小，首屏可同时看到结论与点位；移动端的额外成本主要来自命令区（174）、工具栏（82）与封面纵向堆叠（实施时以 1440 回归截图为准，不在本任务书内给像素基线）。

## 2. 问题清单

> 优先级：P0 = 影响可读性/可操作性；P1 = 首屏与信息层级；P2 = 打磨项。
> 「证据」均为本次 390/360 实测（Playwright 固定数据，截图保存在本地 `test-results/`，不入库）。

### P0-1 首屏看不到结论

- 现象：命令区 174 + 报告头 48 + 工具栏 82 + 封面头部 430 = 结论正文从 773px 开始。
- 证据：见 1.2 表格。
- 建议：
  - 选中报告后，移动端命令区折叠为一行摘要（「600519 贵州茅台」+「新分析」），完整表单改为底部抽屉；
  - 或至少隐藏「服务器选择 + 推送」两行，仅保留输入框与「分析」。
- 验收：选中报告时命令区高度 ≤ 64px；核心洞察正文顶部 ≤ 520px。

### P0-2 报告工具栏占用两行且触控高度不足

- 现象：`重新分析 / 追问 AI / 历史趋势` 挤在一行（每个 36px 高），`完整分析报告` 独占一整行，工具栏 82px。
- 证据：按钮实测 36px 高；工具栏在 390px 下换行成 2 行。
- 建议：
  - 合并为单行 4 等分按钮，高度 44px；文案压缩为「重新分析 / 追问 / 趋势 / 完整报告」；
  - 主操作「完整报告」用主色描边，其余为中性样式（视觉权重不再靠独占一行）；
  - ≤360px 时次要按钮只保留图标 + `aria-label`，完整报告保留文字。
- 验收：工具栏高度 ≤ 48px；全部按钮高度 ≥ 44px。

### P0-3 触控目标普遍偏小

实测可点元素（390px）：

| 元素 | 实测尺寸 | 建议 |
| --- | --- | --- |
| 资讯「刷新」 | 24×16 | 图标按钮 40×40 |
| 「查看运行流」/「复制排障信息」 | 24px 高 | ≥ 40px |
| 「原始分析结果 / 分析快照」折叠按钮 | 38px 高 | 44px |
| 报告工具栏按钮 | 36px 高 | 44px |
| 「Daily Stock Analysis」品牌链接 | 36px 高 | 44px |

- 验收：报告区域内所有交互元素高度 ≥ 44px（纯文本链接可 40px + 足够间距），间距 ≥ 8px。

### P0-4 关联板块横向滚动无提示、末位标签被裁切

- 现象：6 个板块时最后一个标签右侧被裁掉，页面无横向溢出（`docOverflow=false`），但用户不知道还能滑。
- 证据：溢出元素检测到 `div.report-board-chip` 超出视口；`.home-related-board-list` 为 `flex-nowrap + overflow-x-auto`。
- 建议：移动端改为**换行显示**（最多 2 行，超出显示「+N」并可展开），或保留滚动但加右侧渐隐遮罩与「左右滑动」提示。
- 验收：390/360 下不出现被裁切且无提示的标签。

### P1-1 指标带标签 10px，偏小且信息弱

- 现象：`操作倾向 / 情绪指数 / 板块覆盖 / 数据质量` 为 10px + 0.12em 字距，`/100`、`个` 同为 10px。
- 建议：标签提升到 11px（字距降到 0.08em），数值 15→16px；`个` 等量词用 11px。
- 验收：报告正文最小字号 ≥ 11px（免责声明、来源等辅助信息同等要求）。

### P1-2 折叠区折叠态过高，展开后信息重复

- 现象：
  - 「数据上下文」折叠态约 110px：标题 + 副标题 + 4~6 个状态徽章 + 触发来源 + 本次分析输入；
  - 「运行状态」折叠态约 92px；
  - 展开后第一行再次出现「质量分 / 新闻结果数 / 本次分析输入」，与折叠头重复（桌面同样存在，移动端更挤）。
- 建议：
  - 折叠态只保留：图标 + 标题 + 一行摘要（如「可用 3 · 缺失 1」）+ 箭头，≤ 64px；副标题与来源移至展开区；
  - 展开区删除与折叠头重复的 metadata 行，只保留状态计数、数据限制、块详情；
  - 折叠态徽章最多 2 个，其余折叠为「+N」。
- 验收：两张折叠卡折叠态合计 ≤ 140px；展开区不出现折叠头已展示的字段。

### P1-3 空状态占据近整屏

- 现象：`.research-report-empty` 撑满阅读面板（844 高视口下虚线框约 480px，页面仍继续向下），内容垂直居中，页面余下是大片虚线空白；只有「研究记录」一个入口。
- 建议：
  - 改为紧凑空态卡（≤ 320px）：标题 + 一句说明 + 主 CTA「输入代码开始分析」+ 最近 3 条报告/自选快捷入口；
  - 移动端不再强制撑满 `min-height: 680px`。
- 验收：空状态首屏可见至少 1 个主 CTA 与最近记录入口，无大面积空白。

### P1-4 操作入口分散在三处

- 现象：`自选 / 分享` 在封面头部一行，`重新分析 / 追问 / 趋势 / 完整报告` 在工具栏，`研究记录` 在面板头 —— 三处操作区在首屏叠加，视觉重心散。
- 建议（二选一，实施前确认）：
  - 方案 A：把「自选」并入面板头（报告标题右侧），封面只留代码/价格/结论；分享保留在封面；
  - 方案 B：保持现状位置，但工具栏合并为单行后视觉权重下降（成本更低）。
- 验收：首屏操作区不超过两行；同一动作只有一个入口。

### P2-1 长报告缺少导航

- 现象：页面总高 3288px（含资讯约 4000px+），没有目录、没有回到顶部；移动端只能盲滚。
- 建议：
  - 滚动超过 800px 显示「回到顶部」浮动按钮（右下，`env(safe-area-inset-bottom)` 留白）；
  - 可选：面板头右侧「目录」按钮，bottom sheet 列出「一键概览 / 资讯 / 预测市场 / 输入数据块 / 运行状态 / 数据追溯」，点击滚动定位（`scroll-margin-top` 避开 sticky 头）。

### P2-2 滚动上下文与 sticky

- 现状：移动端 window 滚动、阅读区高度自适应；桌面端是阅读区内部滚动（`height: max(680px, 100dvh - masthead)`）。
- 建议：移动端若新增 sticky 报告头，必须用 `--masthead-height` 做偏移，并给章节锚点设置 `scroll-margin-top`；底部浮动控件处理安全区。

### P2-3 触屏无悬浮提示

- 现象：封面「自选」按钮的说明只存在于 `Tooltip`（hover）与 `aria-label`；触屏用户看不到「加入自选 / 移出自选」的文案。
- 建议：移动端直接显示状态文案（「自选」/「已自选」），或点击后 toast 反馈（当前 `actionMessage` 已在右上角显示，可保留）。

### P2-4 深色与横屏

- 现状：深色 token 正常；横屏（844×390）未验证，sticky 顶栏 + 报告头的组合可能挤压阅读高度。
- 建议：纳入验收矩阵，横屏下命令区折叠逻辑一致。

### 非问题（已验证，不需改）

- 页面无横向溢出（`document.scrollWidth == innerWidth`）。
- 策略点位 2×2、情绪/财报并排、正文 13.5/14.5px 行高 1.75+ 在 360px 下可读。
- 深色模式下卡片、指标带、进度条对比度正常。
- Markdown/JSON 区域的 `overflow-x-auto` 不撑破页面。

## 3. 目标与非目标

### 3.1 目标

- **G1** 打开报告后，首屏能看到至少 2 行核心洞察与操作建议标题（核心洞察正文顶部 ≤ 520px）。
- **G2** 报告内所有操作单行可达、触控尺寸 ≥ 44px，操作入口不重复。
- **G3** 折叠区折叠态 ≤ 64px/个，展开后信息不重复。
- **G4** 任何宽度（360/390/414/横屏）下无横向溢出、无被裁切且无提示的内容。
- **G5** 空状态紧凑、有明确下一步。
- **G6** 长报告有回到顶部与章节跳转（P2 可分期）。
- **G7** 桌面端版式零回归。

### 3.2 非目标

- 不改后端接口、报告数据结构、Prompt、通知、飞书卡片。
- 不重做设计语言与配色，不引入 UI 组件库/手势库。
- 不改「研究记录」抽屉与自选、今日、个股栏的交互。
- 不做报告分享图片/PDF 的移动端导出优化（另行立项）。
- 不改变大盘复盘（`MarketReviewReportView`）的结构，只做回归验证。

## 4. 方案设计

### 4.1 首屏结构（选中报告时）

```
┌──────────────────────────────┐
│ 顶栏（64，sticky）             │
├──────────────────────────────┤
│ 命令区折叠条（≤64）            │  600519 贵州茅台        [新分析]
│   点击「新分析」→ 底部抽屉打开完整表单
├──────────────────────────────┤
│ 报告头（48，sticky）           │  分析报告      [目录] [研究记录]
├──────────────────────────────┤
│ 工具条（≤48，单行 4 等分）     │  重新分析 | 追问 | 趋势 | 完整报告
├──────────────────────────────┤
│ 封面                           │  代码/阶段/日期
│                                │  名称 + 价格
│                                │  指标带 2×2
│                                │  01 核心洞察 ← 目标 ≤520px
└──────────────────────────────┘
```

- 命令区折叠仅在 `≤767px` 且 `selectedReport != null` 时生效；桌面不变。
- 完整表单放进 `BottomSheet`（仓库已有 `components/common/BottomSheet.tsx`），保留输入框、服务器选择、推送开关、大盘复盘、分析按钮。
- 「新分析」按钮在报告头或折叠条右侧，保证入口可发现。

### 4.2 工具条

- 单行四等分，高度 44；`data-variant` 继续复用 `home-action-ai` 与 `report-toolbar-primary`，避免新增按钮体系。
- ≤360px：次要按钮隐藏文案（`aria-label` + `title` 保留），主按钮保留文字。
- 「历史趋势」仍为开关语义（打开后按钮高亮、下方展开抽屉），保持现有交互。

### 4.3 指标带与排版下限

- `.report-fact-label`：10px → 11px，字距 0.12em → 0.08em（中英文都适用）。
- `.report-fact-value`：15px → 16px；`.report-fact-unit` 10px → 11px。
- 全报告辅助文本下限 11px：`.report-earnings-source`（10.5）、`.report-strategy-label`（10）、`.report-section-count`（10）等按此校准。
- 中文标签不再使用英文式大写字距（`text-transform: uppercase` 对中文无意义，可保留但不得挤压）。

### 4.4 关联板块

- `≤767px`：`.home-related-board-list` 改为 `flex-wrap: wrap`，最多 2 行；超出部分渲染「+N」按钮，点击展开全部（复用现有 chip）。
- 保留桌面现有的换行策略（≥40rem 容器）。
- 若产品更希望保留横滑，则必须加右侧渐隐 + 首屏「滑动查看更多」提示，二选一在实施前确认。

### 4.5 折叠区

折叠态：

```
[icon] 数据上下文   可用 3 · 缺失 1        ⌄
```

- 隐藏 `.report-collapse-subtitle`（移动端）；
- 徽章最多 2 个，其余聚合为「+N」；
- 高度 44–56px。

展开态：

- 删除与折叠头重复的「质量分 / 新闻结果数 / 本次分析输入」行（桌面同步删除，仅保留差异信息）；
- 状态计数、数据限制、块卡片保持；块卡片在移动端单列（现状已满足）。

### 4.6 触控规范

- 主操作 44×44；次要图标按钮 40×40；相邻按钮间距 ≥ 8px。
- 需要改的具体元素：资讯刷新、查看运行流、复制排障、原始结果/分析快照折叠、品牌链接。
- 用统一的 `.report-touch-target`（或工具类组合）收敛，避免逐处写魔法数。

### 4.7 空状态

- 面板高度改为 `min-height: auto`（移动端），空态卡最高 320px。
- 内容：标题「开始分析」+ 说明 + 主 CTA（聚焦输入框）+ 最近 3 条报告/自选快捷入口（点击即打开报告）。

### 4.8 长报告导航（P2）

- 回到顶部：`position: fixed` 右下，滚动 > 800px 出现，`bottom: calc(16px + env(safe-area-inset-bottom))`。
- 目录：面板头「目录」按钮 → BottomSheet；章节 id 与 `scroll-margin-top: calc(var(--masthead-height) + 报告头高度 + 8px)`。
- 章节来源：`ReportOverview` / `ReportNews` / `PredictionMarketOverviewPanel` / `AnalysisContextSummary` / `ReportDiagnostics` / `ReportDetails`，只在对应内容存在时展示。

## 8. 风险与回滚

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 命令区折叠后用户找不到输入入口 | 高 | 「新分析」按钮常驻 + 抽屉内完整表单；首次进入（无报告）保持现状 |
| 工具栏合并改动现有 testid/aria | 中 | 保留原有 `aria-label` 与点击语义，更新相关 e2e |
| 折叠态隐藏质量分等信息 | 中 | 折叠摘要保留「可用/缺失」总状态，展开后完整展示 |
| sticky 报告头遮挡锚点 | 低 | `scroll-margin-top` + 横屏验证 |
| 触控尺寸增大导致 360px 溢出 | 中 | 360px 纳入 e2e 断言；次要按钮图标化 |
| 桌面回归 | 高 | 所有新规则限定在 `max-width: 47.999rem` / 容器查询内；桌面截图对比 |

回滚：改动集中在展示层，可按提交粒度 `git revert`；移动端规则全部由媒体查询包裹，删除对应规则即恢复现状。
