# 问股「分析过程」产品需求与开发任务书

状态：待实施 · 2026-11-11 · 基线 `57f8d54f`

用户在问股中收到答复后，可以点开该条答复上的「K线获取」「基本面分析」「行情分析」等标签，查看这次分析执行了哪些步骤、调用了哪些 Agent 或工具、取到了什么数据，以及哪里存在缺口。刷新页面或重开历史会话后，仍可查看已保存的过程。

## 当前实现

- 问股答复上方已有一个「思考过程」折叠入口。它显示工具完成次数、工具耗时之和以及按事件展开的列表，用户要展开整段才能找到某项调用。多个并行调用的耗时之和不能代表整轮分析的耗时。[答复渲染](../../apps/dsa-web/src/pages/ChatPage.tsx#L962)
- 单 Agent 执行器会收集运行中进度，并在正常返回成功或失败结果时将步骤与助手消息一起保存。多 Agent 编排器实时发出阶段事件，但其 Chat 完成路径目前只保存答复正文。会话详情和前端已经有 `thinking_steps` 与 `running_progress_steps` 的读取和恢复链路。[单 Agent](../../src/agent/chat_executor.py#L140) · [多 Agent](../../src/agent/orchestrator.py#L518) · [会话详情](../../api/v1/endpoints/agent.py#L367)
- 目前工具事件主要用步骤编号和工具名描述调用。同一步并行调用两次同名工具时，不能可靠地配对开始与完成，也无法根据事件本身准确区分工具超时与普通失败。[工具事件](../../src/agent/runner.py#L754) · [现有事件契约](../agent-stream-events.md)

## 产品需求与验收

### R1 · 每条答复都能回看本轮实际过程

- 在助手答复正文上方，沿用当前折叠入口的位置，展示一行「分析过程」和本轮有记录的标签。首次呈现默认收起，标签按该类首条事件的顺序排列。点一个标签只展开这一类，点击同一标签收起，点击其他标签切换。同一页面上的不同答复独立展开。
- 标签覆盖「分析步骤」「K线获取」「基本面分析」「行情获取／行情分析」及「Agent 协作」。新闻、风险等有明确事件时可显示对应标签。仅取报价时叫「行情获取」。市场指数、板块或其他行情分析步骤实际执行后，才使用「行情分析」。
- 「分析步骤」用简短、可核对的事实说明做了什么，例如「确认讨论标的」「取得日线后计算技术指标」「汇总已取得的数据」。每句话由当前轮已记录的事件或已确认的上下文支持。只有澄清卡片的轮次继续使用卡片本身。没有可展示事件的答复直接显示正文。
- **验收**　让一轮实际执行日线获取、基本面获取与板块分析。完成后三个标签直接可见，默认收起，逐个点击能定位对应记录。再发一轮只取报价的问题，只出现实际发生的标签，展开状态与上一条答复互不影响。

### R2 · 展开后看清调用对象、结果和数据范围

- 工具标签下每次调用占一行，显示可读名称、可确认的标的、状态以及已记录的耗时。数据工具在返回值支持时补充数据来源、数据日期或区间、缓存命中与覆盖范围。基本面优先展示可用模块与缺失模块。多标的查询按每次调用展示完整市场标识，避免同码混淆。
- 「Agent 协作」显示实际执行的阶段或专家，例如技术分析、情报、风险和决策。展开后展示阶段状态、耗时和能够关联的子工具。单 Agent 的通用执行循环归入「分析步骤」。
- 状态使用文字和图标，包含成功、部分可用、失败、超时、已跳过、未完成。数据覆盖与执行状态分别取自真实结果。阶段被预算跳过、工具返回空数据、工具执行失败各有对应说明。并行时保留各自耗时，缺少整轮服务端计时就省略整轮用时。
- 过程区采用现有主题变量、细边框和紧凑标签，展开态用主题强调色与箭头区分。窄屏自动换行，触屏点击区至少 48 px。标签支持 Tab、Enter 和 Space，有可见焦点和展开状态。按界面语言提供中文和英文文案，显示为纯文本。
- **验收**　同一轮并行调用两个同名工具，一个成功、一个超时。两条记录分别显示正确标的、状态和耗时。另测基本面覆盖不完整、风险阶段跳过，以及 320 px 窄屏、深浅主题和键盘操作。

### R3 · 结束、失败、刷新后保留同一份记录

- 正常结束时，运行中的进度切换成该条答复的标签。刷新、切换会话再切回、关闭后重新打开，恢复对应答复的标签、调用状态和顺序。展开偏好只在本次页面内记忆。
- 后端已接受且执行后失败或超时的轮次，保留已记录的步骤，挂在该轮失败结果下。已明确结束但没有收到完成事件的调用显示「未完成」。准备阶段拒绝且没有执行的请求沿用现有错误提示。
- 「停止接收」表示浏览器停止接收回复。后台任务仍可能完成。再次打开或刷新后，运行中的任务恢复进度，已经完成的任务从会话详情恢复结果和过程。单纯断线时按服务端状态恢复，避免重复提交原问题。
- **验收**　先完成一轮，再刷新和切换会话，标签与详情和实时完成时一致。分别模拟接受后失败、超时、主动停止后后台成功。每轮只出现一条助手结果，已采集步骤仍可看。删除会话并以同 ID 重建后，旧任务的延迟事件与结果均不会进入新会话。

### R4 · 过程信息来自可公开的执行事实

- 使用服务端已记录的阶段、工具调用和白名单结果字段生成用户可读摘要。公开事件、历史详情和界面只使用这份摘要数据。模型私有推理、系统提示、供应商协议记录、原始参数与返回、持仓明细、凭据和堆栈留在内部链路。
- 复用现有会话访问边界。首版交付 Web 问股及加载同一 Web 构建的桌面端。分析过程在问股界面内查看，复制和导出继续以答复正文为主。过程整理使用确定性规则，沿用原有模型和工具调用次数。
- **验收**　向历史进度、实时事件和模拟工具结果注入带标记的原始字段、私有推理与异常信息。核对 SSE、会话详情及 UI 只出现许可字段。用旧会话和无工具问答验证可正常阅读，缺失的调用对象、时间、来源和步骤不会被补造。

## 开发任务

### T1 · 定义可展示事件并补齐调用事实

对应 R1、R2、R4。入口为 `src/agent/stream_events.py`、`src/agent/runner.py`、`src/agent/orchestrator.py` 与 `src/agent/agents/base_agent.py`。

- 复用现有 SSE 事件名。开始与完成共享由应用产生的 `call_id`，阶段使用 `stage_id`，阶段内调用携带 `parent_stage_id`。每个 ID 在该轮内唯一。同名并行调用、同一步中的重试、并行专家使用各自 ID。事件按本轮递增的 `sequence` 排序和去重。工具超时、范围拦截、数据为空与正常返回各从执行器已知事实取值。已发出开始事件但仍在排队的工具只表示已发起，开始时间与耗时以实际执行数据为准。
- 对外新增可选 `outcome` 表示本次调用或阶段的结果。约定取值为 `success`、`partial`、`failed`、`timeout`、`skipped`。终态展示时，开始记录缺少可配对的结束事件才标为「未完成」。保留旧 `success`、`status`、`duration` 字段的语义。`duration` 沿用秒为单位。
- 取数层只投影少量按工具定义的 `detail` 字段，例如经过范围校验的标的、数据区间、可读数据源、记录条数、基本面覆盖或缓存状态。公开文案由事件类型、字段和本地化模板生成。执行异常使用稳定的错误类别，向已有 `done.error` 和 `error.message` 提供安全提示，保留内部日志供排查。
- 核对映射。首版以 `get_daily_history` 对应「K线获取」，`get_stock_info` 对应「基本面分析」，`get_realtime_quote` 对应「行情获取」，`get_market_indices` 与 `get_sector_rankings` 对应「行情分析」。技术指标、新闻、风险和专家阶段各按其用途映射。已登记但未单独分类的工具归入「工具调用」。无法识别的历史事件只在能构成安全通用记录时显示。
- **完成条件**　两次并行同名调用乱序结束仍准确配对。阶段与子工具关系能从事件重建。基本面部分可用、行情不可用、缓存命中和预算跳过各有可用样本。后台报告等共享 runner 的其他消费者继续读取原有字段。

### T2 · 统一单 Agent 和多 Agent 的记录保存与返回

对应 R3、R4，依赖 T1。改动入口为 `src/agent/chat_executor.py`、`src/agent/orchestrator.py` 的 Chat 路径、`src/agent/conversation.py`、`src/storage.py`、`src/services/agent_chat_session_service.py` 和 `api/v1/endpoints/agent.py`。

- 复用同一套问股进度收集与白名单投影。向 SSE 发出并写入数据库的过程数据使用同一份公开结构。保留现有 `running_progress_steps_json` 和 `thinking_steps_json` 字段。对运行快照合并写入，保持序号单调，终态持久化前保留最后一份进度。限制单轮事件条数和字段长度，截断时保留明确提示，避免长对话的详情持续膨胀。
- 运行快照写入和清理绑定会话代次及已接受用户消息的锚点。接受新轮次时原子清空旧轮次的运行快照。旧任务只能提交给自身有效的轮次，不得覆盖新轮次进度或清掉新轮次的运行标志。最终答复及其公开步骤在同一写入中保存。预期失败、后端超时和执行异常走一次终态提交，异常发生在终态提交后时沿用已提交结果。
- 在现有 SSE `done` 上追加可选 `assistant_message_id` 和 `thinking_steps`，返回持久化的助手消息 ID 和公开步骤快照。失败的 `done` 同样可引用已保存的结果，前端以该 ID 读取对应消息。连接本身中断或 SSE 等待超时时，以会话详情判断后台是否仍运行。请求未被接受的 `error`、澄清响应和旧客户端沿用原契约。`POST /chat` 复用保存链路，现有非流式响应结构照旧。
- 读历史时兼容没有过程、缺少调用 ID、事件未知及损坏的进度记录。旧记录仅投影可以验证的字段。缺少 ID 时按完成事件独立展示，并保留确有依据的未完成信息。消息正文仍可读取。
- **完成条件**　分别通过单 Agent、多 Agent 的真实 Chat 入口验证流式终态与详情一致，覆盖后端失败和超时、非流式历史恢复、旧版详情，以及 A/B 并发写入和删除重建竞态。

### T3 · 实现答复内标签与进度恢复

对应 R1–R4，依赖 T1、T2。改动入口为 `apps/dsa-web/src/pages/ChatPage.tsx`、`stores/agentChatStore.ts`、`api/agent.ts`、`i18n/uiText.ts` 和现有样式。视觉沿用仓库的 [DESIGN.md](../../DESIGN.md)。

- 从 Chat 页面现有折叠块提取过程组件。用同一映射将实时进度、终态快照和历史记录整理成可读的调用项。按 `call_id` 和 `stage_id` 配对，重复调用按实际次数计数。标签展开状态按会话实例与助手消息 ID 保存于页面内。标签用原生按钮实现，绑定 `aria-expanded` 和 `aria-controls`。验证主题、键盘、窄屏及读取长明细时的滚动稳定性。
- 正常完成时使用服务端助手消息 ID 与过程快照。主动刷新、轮询恢复及流式完成共用消息归并规则，保证一条服务端助手消息只渲染一次。接收晚到的 SSE 或详情前核对请求归属、会话代次与页面实例。对于旧服务端，继续使用该轮已收集的实时进度和现有详情恢复路径。
- 成功答复、失败提示、澄清卡片继续沿用各自入口。后台仍运行时使用现有恢复和轮询机制，轮询结束后将过程挂到最终消息。复制、导出和消息 Markdown 正文沿用现有入口与格式。
- **完成条件**　R1–R4 的样例在 Web 可验收。刷新、掉线、重复或延迟响应均不会产生重复答复、串用记录或错误完成状态。旧历史仍可阅读。

### T4 · 验证、文档和发布准备

依赖 T1–T3。先覆盖用户可见入口，再跑仓库门禁。

- 后端回归扩展 `tests/test_agent_stream_events.py`、`tests/test_agent_chat_executor.py`、`tests/test_agent_chat_api.py`、`tests/test_agent_sse_cleanup.py`、`tests/test_agent_chat_session_service.py` 及现有多 Agent 测试。覆盖乱序并行、结果白名单、失败持久化与跨会话隔离。执行 `./scripts/ci_gate.sh`。
- Web 扩展 `ChatPage.test.tsx`、`agentChatStore.test.ts` 与 Agent API 测试，覆盖标签状态、失败与超时、流式与历史一致性、旧字段、轮询竞态及停止接收。进入 `apps/dsa-web/` 执行 `npm ci`、`npm test`、`npm run lint` 和 `npm run build`，验证桌面端加载对应 Web 产物。
- 登录后用真实问股回合验证服务端事件与页面展开，至少覆盖单 Agent 和多 Agent 的代表路径。PR 附桌面和移动端截图，展示完成时的标签、展开状态和一种异常状态。记录真实模型或桌面联调中仍未验证的项目。
- 更新 `docs/agent-stream-events.md`、中英文 `docs/full-guide*.md` 和 `docs/CHANGELOG.md` 的 `[Unreleased]` 扁平条目。发布前备份会话库，优先验证旧 Web 可读取新 API。出现回归时恢复上一版 Web/API，保留已保存的会话及过程字段，并验证旧版历史正文可读。

## 首版交付边界

首版完成 T1–T4。全量工具输出浏览、过程导出、跨轮统计和重新执行单个工具另行立项。以上为基于仓库代码的需求设计，运行时行为与视觉样式按实施后的验收结果确认。
