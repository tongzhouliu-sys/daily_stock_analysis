# 问股历史回看 · 产品需求与开发文档

状态：待实施 · 2026-11-11 · 代码基线 `88874029`

## 产品需求

用户从问股左侧的历史列表重新打开一次会话时，可以在每条助手答复上方展开「思考过程」，查看这次问答执行了哪些分析步骤、调用了哪些 Agent 和工具，以及调用结果。刷新页面、切到其他会话再切回来，看到的仍是这条答复对应的记录。

### R1 · 每条答复独立回看

- 沿用答复正文上方的「思考过程」入口，默认收起。展开后按执行顺序展示分析步骤、Agent 阶段和工具调用。有记录时显示名称、状态和耗时。并行调用各自显示耗时，整轮耗时仅在有整轮计时时展示。
- 一段会话有多轮问答时，每条答复只显示本轮过程，展开状态互不影响。单 Agent 显示实际执行的步骤和工具，多 Agent 显示实际启动的专家或阶段，工具归属明确时显示在对应阶段下。使用中英文界面文案，支持鼠标、触屏和键盘操作。
- 回看只读取已保存记录。过程摘要取自实际发生的应用事件，例如「技术分析 Agent 完成」「获取日线数据失败」「正在生成答复」。页面无需重新发问或调用模型、行情和搜索工具。

### R2 · 恢复实际执行结果

- 正常完成时，实时进度收进对应答复的折叠区。重新打开后，步骤、调用对象、状态和顺序与已保存记录一致。
- 已开始执行的问答失败或超时时，在本轮失败结果上保留已完成的步骤。已发起且无法确认结果的调用显示「未完成」。服务端明确记录超时、失败或跳过时，使用对应状态。
- 「停止接收」后重新打开会话，如果服务端仍在执行，显示其最新进度并沿用现有轮询。服务端执行结束后，在对应答复中显示最终记录。断线恢复同样从会话详情确认状态，避免再次提交问题。

### R3 · 兼容已有历史

- 有可用过程字段的旧答复，按实际保存的字段展示。无记录的普通答复可显示「暂无可回看的分析过程」，正文仍可阅读。已识别为仅澄清的轮次沿用澄清交互。
- 历史字段缺失或损坏时，只省略受影响的过程。没有可靠关联信息的旧调用按独立记录展示。没有保存的步骤、调用次数、结果和耗时不作推断。

## 代码现状

- Web 点击历史会话会读取会话详情。首次加载、切换和轮询已有 `thinking_steps` 到 `thinkingSteps` 的映射。「思考过程」只在助手消息携带非空步骤时渲染。现有入口可以复用。[会话切换](../../apps/dsa-web/src/stores/agentChatStore.ts#L507) · [历史映射](../../apps/dsa-web/src/stores/agentChatStore.ts#L350) · [折叠入口](../../apps/dsa-web/src/pages/ChatPage.tsx#L963)
- 单 Agent 已采集进度，正常返回成功或失败时会随助手消息保存。执行抛异常时会进入清理路径，已收集的步骤可能没有对应的终态消息。多 Agent 问股走独立执行器，能发出实时阶段事件，保存助手消息时未传入步骤。[执行器选择](../../src/agent/factory.py#L628) · [单 Agent](../../src/agent/chat_executor.py#L140) · [多 Agent](../../src/agent/orchestrator.py#L522)
- 流式结束事件已能携带 `assistant_message_id` 和 `thinking_steps`。前端成功时仍用临时 ID 和浏览器收集的事件构建答复，失败时走提示分支。实时能看到步骤，只能说明事件已到达浏览器。会话详情须有同一条答复的持久化记录才能回看。[结束事件](../../api/v1/endpoints/agent.py#L606) · [前端结束处理](../../apps/dsa-web/src/stores/agentChatStore.ts#L659)
- 现有运行快照按会话 ID 写入和清理，终态消息另有代次及已接受用户消息的校验。详情直接解码进度 JSON。重叠请求、删除后同 ID 重建、损坏历史字段需要专门覆盖。[会话快照](../../src/storage.py#L3930) · [消息与运行状态写入](../../src/storage.py#L4094)

以上为仓库代码核对结果。复现时先在会话详情定位对应的助手消息。如果响应有 `thinking_steps`，检查前端恢复及展示。如果响应缺少步骤，检查该消息的 `thinking_steps_json`，并用一轮新问答验证实际运行的执行器是否保存步骤。旧记录和新问答分别验证。

## 开发方案

### T1 · 统一问股的过程采集和终态保存

1. 流式与非流式问股共用过程采集逻辑。复用 `src/agent/chat_executor.py` 中现有采集路径，接入 `src/agent/orchestrator.py` 的问股执行路径。范围限于问股，保留其他报告入口使用的事件契约。
2. 基于 `src/agent/stream_events.py` 的既有事件类型投影可公开字段。允许步骤序号、已登记的工具或阶段标识、关联 ID、状态及有效耗时。中文和英文描述由受控文案生成。模型私有推理、提示词、内部诊断、原始工具参数与返回及异常堆栈留在内部链路。现有 `detail` 可能带 `result_preview`，直接透传会暴露原始工具输出。实时事件、存储和详情读取采用同一白名单，历史数据也经过投影。[工具详情构建](../../src/agent/runner.py#L775)
3. 复用 `thinking_steps_json` 保存答复级终态记录，复用 `running_progress_steps_json` 保存运行进度。并行事件按本轮采集顺序归档，开始和完成用本轮唯一的调用或阶段 ID 配对。现有工具 `call_id` 由单批次计数产生，不能作为整轮唯一键。缺少配对证据的旧事件独立展示。限制单轮记录条数与字段长度，保留终态事件，发生截断时返回明确标记。[工具调用 ID](../../src/agent/runner.py#L902)
4. 在 `src/storage.py` 的事务内用 `session_generation` 和已接受用户消息锚点校验写入归属。运行标志和运行快照只由当前归属轮次更新和清理，旧轮次的迟到结果不得清除新轮次进度。有效轮次的答复与步骤在同一条消息写入，成功、返回失败、执行超时或抛异常均走单一终态路径。该轮完成提交后才允许清除其运行标志，且重复处理同一终态要复用已提交结果。保持既有会话状态冲突和删除语义。

### T2 · 用现有接口返回已保存记录

- `GET /api/v1/agent/chat/sessions/{session_id}` 继续在 `messages[].thinking_steps` 返回各助手消息的步骤。字段缺失、`null` 或空数组均按无记录处理。坏 JSON 或未知事件仅影响对应过程，正文及会话状态仍可读取。`is_running` 和 `running_progress_steps` 只表示当前运行轮次。保持 `limit` 兼容性，验证长会话的运行恢复路径能够定位最新结果，避免默认从最早截断的 100 条窗口遮住本轮答复。
- `POST /api/v1/agent/chat/stream` 的 `done` 在终态消息成功保存时返回 `assistant_message_id` 与该消息的 `thinking_steps`，失败结果也遵循此规则。会话详情当前使用字符串消息 ID，客户端将 SSE 返回的数值 ID 归一化为同一种字符串。失败时用详情加载已保存的安全提示与步骤，沿用 `success`、`error_code` 的既有含义。连接等待超时后的真实运行状态由详情确认。保留未接受请求的 `error`、澄清载荷和已有客户端字段。
- `POST /api/v1/agent/chat` 复用同一保存逻辑，过程经详情回看，调用方继续使用现有响应结构。读取沿用现有会话访问规则。

会话详情与 `done` 对齐示例。为突出字段，仅列出与过程有关的部分。

```json
{
  "id": "42",
  "role": "assistant",
  "content": "本次分析已完成。",
  "thinking_steps": [
    {"type": "stage_start", "stage": "technical", "stage_id": "s1"},
    {"type": "tool_start", "tool": "get_daily_history", "call_id": "c1", "parent_stage_id": "s1"},
    {"type": "tool_done", "tool": "get_daily_history", "call_id": "c1", "parent_stage_id": "s1", "success": true, "duration": 0.8},
    {"type": "stage_done", "stage": "technical", "stage_id": "s1", "status": "completed", "duration": 1.2}
  ]
}
```

`GET /api/v1/agent/chat/sessions/session-example` 的 `messages` 中包含上面的记录。对应 `POST /api/v1/agent/chat/stream` 的 `done.assistant_message_id` 为 `42`，`done.thinking_steps` 返回同一组步骤。耗时单位为秒，事件名和其余字段遵循现有契约。[问股流式事件](../agent-stream-events.md)

### T3 · 让流式完成和历史详情使用同一展示逻辑

1. 在 `apps/dsa-web/src/api/agent.ts` 和 `stores/agentChatStore.ts` 共用消息与进度解析逻辑。流式结束优先使用服务端消息 ID 和过程快照。初次加载、切换会话、刷新、轮询都用同一映射。`done` 同时携带有效消息 ID 和空数组时，以空数组为准。旧服务端缺少有效消息 ID 或快照时，当前页面可展示已收到的实时事件，重开以详情记录为准。
2. 按服务端消息 ID 更新或归并消息。轮询允许为已有 ID 补齐步骤，同时保留消息级的临时界面状态。处理晚到的 SSE 或详情前核对会话 ID、代次和当前请求归属，避免快速切换时串数据或重复插入答复。主动停止接收、断线和失败恢复均不得自动重发问题。
3. 在 `ChatPage.tsx` 复用现有折叠区和样式，按钮关联面板并提供 `aria-expanded`。展开状态以会话代次和助手消息 ID 为范围，历史重开默认收起。单次调用的开始与结束合并为一行，缺少稳定 ID 时只在无歧义的情况下配对。展开后用文字表达状态，保证长工具名称在移动端可换行。沿用项目视觉规范。[页面渲染](../../apps/dsa-web/src/pages/ChatPage.tsx#L1437) · [DESIGN.md](../../DESIGN.md)

## 验收与发布

1. **从历史打开两轮问答**　先问两次并使两轮调用不同工具，切走、切回、刷新各一次。两条答复均可展开，仅显示各自的步骤和调用。打开或展开时，网络请求中没有新的问股提交。
2. **单 Agent 与多 Agent**　通过实际问股 API 分别完成一轮，核对 `done` 的消息 ID 和步骤与详情一致。多 Agent 的技术、风险等阶段按实际执行结果展示。构造两次同名工具并行且乱序结束，确认各自状态匹配。验证非流式问答也可回看。
3. **失败与恢复**　在已有步骤后触发执行失败和超时，确认历史中有对应失败结果及步骤。停止接收或断开后重开，分别验证仍在运行和已完成两种情况。只出现一条终态答复，未完成调用没有被显示为成功。
4. **会话隔离与旧记录**　覆盖快速切换、过期响应、同会话旧请求迟到、删除后同 ID 重建和超过默认详情条数。另测缺字段、损坏 JSON、未知类型及仅澄清场景。正文可读，步骤不串轮。向工具结果和旧过程记录注入可识别的敏感标记，核对实时、详情及界面均未输出该标记。
5. **界面与回归**　登录后在桌面和窄屏实际打开历史会话，验证展开、键盘和中英文文案。扩展 `tests/test_agent_chat_executor.py`、`tests/test_agent_chat_api.py`、`tests/test_agent_chat_session_service.py`、`tests/test_agent_sse_cleanup.py` 和 `ChatPage.test.tsx`、`agentChatStore.test.ts`。执行 `./scripts/ci_gate.sh`，并在 `apps/dsa-web/` 执行 `npm ci`、`npm test`、`npm run lint`、`npm run build`。验证桌面端加载对应的 Web 构建产物，PR 附历史答复展开及异常状态截图。
