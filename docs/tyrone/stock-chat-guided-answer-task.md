## 2. 首次引导产品规则

### 2.1 何时询问

- “首次”指用户点击「新建对话」后的首次有效问题。刷新、重新登录、另开浏览器标签页或恢复历史，不重新触发。
- 服务端依据会话代次与引导状态判断，不能只用 localStorage 或消息数量。
- 每个新会话先展示 1–5 道选择题再开始研究；通常 2–3 题，复杂场景最多 5 题。信息已充分时，只展示一道「按这些条件分析？」确认选择题。
- 同会话追问沿用背景，历史会话不强制补问。用户切换标的后清除原标的专属持仓信息；周期等会话偏好显示为可修改背景。
- 用户可修改「本次分析背景」，新选择影响下一次分析；历史答复保留当时快照。

### 2.2 选择题题库与分支

使用受控题库和规则分支。模型可辅助识别意图、排序和润色题干，服务端校验枚举、类型、依赖和数量；不能让模型自由输出不可解析的表单或追加第 6 题。

| 维度 | 示例题干 | 选项示例 | 使用条件 |
| --- | --- | --- | --- |
| 对象 | 你关注哪个市场的中芯国际？ | A 股 688981／港股 HK00981／暂不确定／只了解公司业务 | 对象有歧义时优先，复用真实标的解析 |
| 目标 | 这次最想解决什么问题？ | 判断是否值得关注／评估已有持仓／了解涨跌原因／学习分析方法 | 原文未明确目标时 |
| 周期 | 你更关注多长时间？ | 数日内／1–4 周／1–6 个月／6 个月以上／还没确定 | 趋势、估值和持仓问题 |
| 持仓 | 你目前持有这只股票吗？ | 尚未持有／已持有，关注盈利保护／已持有，关注回撤／暂不提供 | 持仓信息会改变回答时 |
| 风险侧重 | 这次分析优先考虑什么？ | 控制下行风险／机会与风险均衡／愿意接受较大波动／暂不确定 | 决策类研究，不等于正式风险评级 |
| 研究重点 | 哪些内容对你最有帮助？ | 趋势与关键位置／业务与估值／新闻与事件／风险与反例／综合分析 | 多选最多 2 项；综合分析与其他项互斥 |
| 阅读方式 | 你希望怎样阅读答案？ | 先看重点／详细研究／用通俗语言解释 | 概念问题或其他信息已充分时 |

上述为题库，不能全部依次询问。先解决对象歧义，再补目标、周期和相关约束。原文明确提供的信息标记「来自你的问题」，不重复询问；推断信息标记「待确认」，不得当作用户选择。未提供持仓不等于空仓，未知风险不等于均衡。

典型路径：

- 「帮我看看 AAPL」：目标 → 周期 → 风险侧重；选择评估持仓才补持仓题，总数不超过 5。
- 「没有持仓，研究 AAPL 未来半年，优先控制风险」：一题确认，选项为「按这些条件分析／调整条件／只做通用解读」。
- 「什么是市盈率」：只问阅读方式，不问持仓和风险。
- 报告追问：使用服务端确认的报告引用及标的，只补缺失背景；报告提及的持仓不当作客户持仓。

### 2.3 操作与边界

- 偏好题提供「暂不确定／暂不提供」，不要求输入金额、成本、账号或自由文本。
- 保留「按通用背景分析」次要操作；未选择信息保存为 unknown，不生成隐藏默认偏好。对象未确认时，仅允许一般解释，不能针对猜测标的给具体判断，也可返回修改原问题。
- 新流程把股票澄清并入题组并计入 5 题上限，不再弹第二套问询。保留旧客户端原有澄清路径；新流程不倒计时、不自动提交。
- 选择后点击「下一题」，不自动跳题；可以返回修改。改变前置答案时，服务端删除失效分支及其答案，确认页同步更新。
- 确认选择题也计入题数；选择「调整条件」后重新规划剩余题目，总上限仍为 5，不用追加小问绕过上限。多标的比较仅沿用已有入口支持的范围，不借此扩展股票对象执行权限。
- 最后点击「按这些背景开始分析」才提交正式研究。题组只补上下文，不直接产生交易授权。

### 3.2 四段连续体验

1. **原问题**：问题保留在对话区，短暂显示「正在准备本次引导」，不启动研究工具。
2. **逐题点选**：助手区域展示「先了解一点，让回答更贴近你」，说明「只需点选，可随时返回修改」。题号、分段进度、选项短标题和一句解释清楚可见。
3. **确认背景**：列出标的、目标、周期及相关约束；未提供写「未提供」。每项可修改，只有一个主按钮「按这些背景开始分析」。
4. **研究与阅读**：题组收成「本次分析背景」。沿用真实分析进度，最后增加「正在整理重点与核对表达」，完成后显示精排回答。

桌面保留历史侧栏和原输入区，正文宽度建议 720–800 px；空间充分时选项为 2 列。手机采用单列，操作区避开软键盘与安全区，不额外弹全屏问卷。问卷期间输入区提示「先完成上方选择，或返回修改问题」。

```text
你：帮我看看 AAPL

先了解一点，让回答更贴近你                 2 / 3
━━━━━━━━━━━━━━────────
你更关注多长时间？
这会帮助我选择分析尺度。

[ ○ 数日内          ]  [ ○ 1–4 周          ]
[ ● 1–6 个月        ]  [ ○ 6 个月以上      ]
[ ○ 还没确定        ]

上一题                 按通用背景分析     下一题 →
```

### 3.3 精排阅读

- 首屏突出 1–3 句结论、适用背景和影响判断的重大限制。
- 研究问题采用「结论 → 依据 → 改变判断的条件 → 风险 → 来源」；有内容才显示章节，不凑模板。
- 概念问题采用「直接解释 → 一个例子 → 容易误解的地方」；比较问题围绕共同维度；事件问题区分事实与可能影响。
- 依据通常 3–5 项，每项连接事实与解释。推断明确标识；关键位置、概率、目标价仅在已有数据支持时出现。
- 重大风险与失效条件默认可见；深入依据与来源详情可以折叠。长答案按实际标题生成页内目录，短答案不显示目录。
- 使用短段落、克制加粗、简洁表格与充足段间距，不整段加粗、不堆图标，不把每段包装成卡片。
- 来源显示实际日期、粒度及可核验的链接或数据源名称。EOD 不写成实时行情，无 URL 不编造链接。
- 末尾最多 3 个相关追问按钮，只有点击才发起下一轮，并沿用确认背景。

服务端最终 Markdown 为正文真源。前端复用 react-markdown、remark-gfm，按语义节点增强阅读；未知结构仍完整展示，不能按中文标题字符串硬切内容。复制、历史、导出和下一轮上下文使用同一份最终正文；折叠不删除导出内容。复用现有导出模块。

### 3.4 状态、主题与可访问性

- 生产复用现有主题 token，铜色只强调主操作与选择；涨跌色独立。沿用 0–4 px 圆角、1 px 分隔线，无炫光或装饰渐变。
- 正文建议 16 px、中文行高 1.75–1.85，辅助字至少 12 px，标题 20–24 px，数字采用等宽数字。
- 原生 radio／checkbox 与 fieldset／legend；选择态有勾选及文字，不只靠颜色。支持 Tab、方向键、Space、Enter 与可见焦点。
- 触控区至少 48 px，覆盖 320／390／768／1440 px、深浅主题、中英文及减少动画模式；表格单独滚动，不撑破页面。
- 动态进度简短播报，换题后焦点进入新题；用户阅读旧消息时不强制滚到底部。
- 引导准备失败：保留问题，允许重试或通用分析；保存失败保留本地答案并明确未保存，不假报成功。
- 刷新恢复服务端草稿和版本；无法恢复时明确提示，不自动研究。
- 断线和「停止接收」沿用现有语义，后台可能继续；重新打开以服务端结果为准。
- 编辑失败或超时回到原有合格回答并做确定性排版，不显示「优化完成」，不吞掉成功研究结果。

## 4. 回答精编 skill

名称 `stock-answer-editor`，显示名称「问股回答精编」。完整输入输出、指令草案与反例见[专用 skill 规格](stock-answer-editor-skill-spec.md)。

```text
确认背景 → 研究执行 → 最终风险和决策收敛
→ 回答精编 skill → 事实与结构校验 → 持久化最终答案 → done / HTTP 响应
```

这是应用运行时编辑环节，不进入缠论等策略选择器，不参与投票、不占用户 3 个策略名额。单／多 Agent、流式／非流式共用一个编辑服务。

最多一次无工具模型请求，复用模型路由、用量统计和预算。简单答复允许确定性规范化；不重复调用行情或搜索，不新增无限自评循环，不先展示草稿再整体替换。

## 5. 数据与接口契约草案

以下为拟新增设计，T1 根据当前迁移机制定稿。路径前缀 `/api/v1/agent`。

| 结构 | 主要字段 | 不变量 |
| --- | --- | --- |
| IntakeDraft | intake_id、schema_version、session_id、session_generation、base_state_version、revision、original_message、questions、answers、status | 服务端保存；1–5 题；pending／confirmed／skipped／invalidated |
| Question | id、dimension、type、title、help、options、required、depends_on | 仅 single／multiple；受控选项；无循环依赖 |
| Answer | question_id、option_ids、source | 区分 explicit_message／user_choice／unknown；未确认推断不得注入 |
| AnalysisBrief | brief_version、object_scope、goal、horizon、position、risk_focus、focus_areas、reading_style、unknown_fields | 服务端枚举重建，冻结到每轮 |
| AnswerMeta | schema_version、editor_version、editor_status、brief_snapshot、source_refs | applied／normalized／fallback；旧消息可缺省 |

背景进入单 Agent 提示词和多 Agent 共享上下文，作为用户约束而非系统指令。原文明确变更优先于旧背景，冲突无法解析先澄清。历史压缩仍保留当前 brief，不能仅靠摘要记忆。

| 接口 | 请求要点 | 返回与行为 |
| --- | --- | --- |
| POST `/chat/intake` | message、session_id、session_generation、request_id、skills、既有 context | 创建／恢复 Draft，不执行研究、不提交正式问答 |
| PATCH `/chat/intake/{intake_id}` | expected_revision、answers、action=save／confirm／skip | 校验、分支更新、revision 递增；确认后返回 brief 预览 |
| POST `/chat`、`/chat/stream` | 保留原字段；追加 interaction_version=1、intake_id、intake_revision | 核对原问题、代次及确认状态，原子接受研究 |
| GET `/chat/sessions/{session_id}` | 沿用现有请求 | 可选追加 pending_intake、analysis_brief、消息级 answer_meta |

创建请求示例：

```json
{"message":"什么是市盈率？","session_id":"demo-session","request_id":"demo-intake-request","context":{"report_language":"zh"}}
```

创建响应示例：

```json
{
  "intake_id": "demo-intake",
  "schema_version": 1,
  "session_generation": "demo-generation",
  "base_state_version": 0,
  "revision": 1,
  "status": "pending",
  "questions": [{"id":"reading","dimension":"reading_style","type":"single","title":"你希望怎样了解？","help":"选择适合你的解释方式。","required":false,"depends_on":null,"options":[{"id":"plain","label":"通俗解释"},{"id":"detailed","label":"详细原理"},{"id":"unknown","label":"暂不确定"}]}],
  "answers": []

```

确认请求与响应示例：

```json
{"expected_revision":1,"answers":[{"question_id":"reading","option_ids":["plain"]}],"action":"confirm"}
```

```json
{"intake_id":"demo-intake","revision":2,"status":"confirmed","brief_preview":{"reading_style":"plain","unknown_fields":[]}}
```

正式请求保留 message 原文，附 interaction_version=1、intake_id、最新 intake_revision 和 session_generation。现有 content 继续为 Markdown，done、非流式响应及详情可追加 answer_meta；状态版本、进度和消息 ID 继续复用。

错误使用既有封装：422 `invalid_intake_answer`；409 `intake_revision_conflict`、`intake_not_confirmed`、`intake_message_mismatch`；会话代次沿用 `session_state_conflict`。草稿不存在／不可访问时沿用现有访问边界，不暴露其他会话。

### 5.1 持久化和并发

- 在现有数据库体系增加草稿表或专用 JSON 列，由 T1 核对迁移方式后选择，不另建数据库。草稿可显示于历史并标记「待补充」，不伪造正式消息数。
- 原问题只在研究接受时提交一次。草稿确认与研究接受分开，关闭页面后的已确认草稿可恢复。
- 草稿消费、brief 快照、用户消息和请求幂等锚点必须在同一事务收敛；双击、重试和双标签页只启动一次研究。重复请求读取原任务状态，不另造 SSE 重放系统。
- 核对 session_generation、intake revision 和 base_state_version，拒绝过时草稿；删除后同 ID 重建不能被旧任务写入。
- accepted 只表示研究真正接受；等待选择不占用长连接。最终正文与元数据同写后再发 done。
- 草稿不能作为另一条公开助手答案写历史。供应商 trace 可保留原始调用，但下一轮可见上下文须采用最终答复，避免旧草稿混入。
- 旧客户端不带 interaction_version 保留原流程；新 Web 遇旧 API 明确提示能力不足后允许原有直接问答，不假装已引导。能力字段不承担权限控制，所有接口保持原认证与会话访问校验。

## 7. 验收与质量门槛

1. 新会话首次展示 1–5 题；确认前无研究 Agent、行情或搜索调用；第二轮和刷新不重问。
2. 信息完整只确认一次；概念问题不问持仓风险；快捷提问、报告及扫描器入口一致。
3. 股票歧义合并，通用分析不把未知对象、持仓和风险当成已知。
4. 改前置答案后服务端删除失效分支；非法枚举、超量多选、伪造 profile 和恶意题干被拒绝。
5. 草稿保存／确认／接受阶段都可恢复；双击、重试、双标签页只启动一次研究。
6. 切会话、删除重建、迟到详情／SSE 和过时 revision 不串背景、不串结果。
7. 单／多 Agent × 流式／非流式四组入口经过同一编辑服务，最终答案不被旧保存路径覆盖。
8. 数值、市场、币种、日期、条件方向、否定、最终动作、引用保持一致；“不能确认买入”不能改成“可以买入”。
9. 过期、部分、冲突数据及风险否决保留显著限制；EOD 不因用户短期偏好被写成盘中证据。
10. 编辑 timeout、异常、空输出、超长、无预算与校验失败有界回退，不吞掉合格研究结果。
11. 实时、历史、复制、所有现有导出和下一轮可见上下文一致；旧／损坏元数据不影响正文。
12. 停止接收不误报后台取消，编辑中断线后能恢复结果，不重新启动研究。
13. 320／390／768／1440 px、深浅主题、中英文、键盘和减少动画模式可用，无整页溢出。
14. 固定评测集至少 24 例；按相关性、清晰度、证据完整性、条件表达、篇幅适配各 1–5 分，均分目标 ≥4 且不低于原答复。关键事实或风险回归直接阻断，不能由平均分抵消。
15. 记录引导完成／跳过、编辑失败类别、额外耗时及 token，默认不记录选择内容和持仓原文。无模型题库准备 P95 目标 ≤500 ms；需模型识别路径目标 ≤3 s，超预算回受控题库；编辑 deadline 为剩余总预算与 8 s 的较小值，预算不足直接规范化。以上为待实测目标，不是已达到的指标。

后端优先 `./scripts/ci_gate.sh`，扩展现有 chat API、session service、chat executor、多 Agent 和 SSE 测试，并增加针对引导／编辑真实风险的用例。Web 在 `apps/dsa-web/` 执行 `npm ci`、`npm test`、`npm run lint`、`npm run build`，扩展 ChatPage、store、API 测试。Desktop 验证共享 Web 加载，涉及集成改动再构建桌面。测试不访问生产会话库，不发真实通知。

验收需登录后的真实完整流程与一次导出，记录真模型单／多 Agent、Desktop 和未覆盖项；构建或原型通过不能当作已实现。
