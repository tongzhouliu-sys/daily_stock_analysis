# 首页股票报告「追问 AI」开发需求

本文定义交互与验收口径。实施需用户另行确认。

## 用户场景

用户在首页查看刚生成的股票分析报告，点击「追问 AI」，进入问股后直接问「这个止损位是怎么算出来的？」。问股应知道「这个」指刚才打开的那份报告。用户在发送前能确认报告来源，发送后还能围绕同一份报告继续追问。

## 现状

- 首页已将当前报告的 `recordId`、股票代码和名称传给问股。问股从历史接口异步读取报告，成功时会尝试附上分析摘要、策略点位、历史价格和已有的市场结构字段。[首页入口](../../apps/dsa-web/src/pages/HomePage.tsx#L927) · [报告上下文加载](../../apps/dsa-web/src/utils/chatFollowUp.ts#L145)
- 现有测试明确允许加载期间发送，此时请求可能只带股票代码和名称。读取失败或对象不匹配会退回同样的基础信息。页面只提示加载中，成功后没有显示引用的是哪份报告。首轮被服务端接受后，页面会清理本次报告上下文。[发送逻辑](../../apps/dsa-web/src/pages/ChatPage.tsx#L909) · [现有回归用例](../../apps/dsa-web/src/pages/__tests__/ChatPage.test.tsx#L1385)

以上来自仓库代码与测试断言，线上登录后的交互和实际模型输入尚未实测。

## 需求与验收

### R1 · 从当前报告发起独立追问

- 从首页刚完成或从历史记录选中的个股报告点击「追问 AI」，进入新的问股草稿。保留可编辑的默认问题，等待用户主动发送。原有会话仍可从侧栏打开。
- 以点击时所选报告的记录 ID 定位来源。同一股票有多份报告时，选择较旧的一份也应打开该份。缺少可引用记录的入口应有明确提示。大盘复盘、信号扫描证据和普通问股沿用各自入口。
- **验收**　为同一股票准备两份止损位不同的报告。从旧报告点击追问，新草稿显示旧报告的时间和来源，未触发模型请求，原会话内容无变化。

### R2 · 在输入框附近显示报告状态

- 加载时显示「正在加载分析报告」，允许编辑问题。报告校验完成前，发送按钮、回车及其他发送入口均不得提交带报告的草稿。用户可主动移除报告，再按普通问股发送。
- 加载成功后显示「已加载分析报告」，附股票名称、市场代码、报告生成时间和「查看原报告」入口。链接定位原记录。状态放在输入区的首层，移动端、键盘操作和深浅主题均可识别。
- 读取失败、报告已删除、访问受限、身份不匹配或无可用正文时，明确提示「未能载入分析报告」，保留输入并提供「重试」和「移除报告」。移除动作应明确说明接下来按普通问股发送。发送前校验失败同样回到可恢复状态。
- **验收**　延迟报告接口并立即按回车，确认没有问股请求。接口成功后能打开准确的原报告。模拟失败与重试，确认问题草稿保留，用户知晓当前是否附带报告。

### R3 · 让模型使用所选报告的内容

- 服务端按指定记录读取和校验报告，将报告标识、生成时间、分析摘要、主要结论、风险与策略点位等已有内容作为历史资料交给问股。报告当时价格、涨跌幅和市场结构可在字段存在时带入。缺失值保留缺失，较长内容按预算截取并标明。报告属于历史资料，模型结合新行情作答时应区分日期与来源。
- 报告加载完成后，用户可以直接问「这个止损位怎么来的？」等不重复代码的问题。首条用户问题被服务端接受时，已验证报告可为无对象冲突的追问建立主讨论对象。明确切股、比较和身份歧义仍遵循现有对象判定规则。
- **验收**　删除默认问题里的股票代码，发送「这个止损位怎么来的？」。在实际模型调用前捕获输入，确认其中有旧报告的记录标识、生成时间和特有止损位。单 Agent、多 Agent 及流式与非流式入口按同一语义验证。

### R4 · 延续引用并隔离会话

- 首轮成功接受报告后，当前会话显示「本会话引用的报告」。同股追问继续引用同一记录，刷新或重新打开会话时恢复来源。报告仍在加载的草稿刷新后应能重新加载指定记录。
- 打开其他会话、发起普通新会话或明确切换到另一标的时，不将旧报告带入新对象。比较场景仅在原主对象符合现有范围规则时将报告标注为该对象的历史资料。服务端未采纳报告的澄清轮次或切股轮次不得显示已引用。
- **验收**　首轮之后刷新页面，继续问「报告里还列了什么风险？」并验证模型输入仍引用原记录。再切换到另一股票或打开另一会话，验证发送内容和输入区来源均不会串用原报告。快速从报告 A 切到 B 时，晚返回的 A 也不能覆盖 B 的草稿。
