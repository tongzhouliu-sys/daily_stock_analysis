# 首页股票报告「追问 AI」开发任务

实施需用户另行确认。验收以 [开发需求 R1–R4](stock-report-follow-up-requirements.md#需求与验收) 为准。

## T1 · 读取指定报告并校验讨论对象

对应 R1、R3。复用 `HistoryService.get_history_detail_by_id` 的主键读取与 `api/v1/endpoints/history.py` 的历史报告字段来源，以及 `src/services/agent_chat_session_service.py` 的证券身份和范围规则。

- 在现有问股请求中追加可选 `context.report_record_id`，接收正整数历史记录主键。省略时维持普通问股行为或继续已确认的报告引用，显式 `null` 表示用户移除引用。报告追问由服务端按主键取数，采用现有历史访问边界并校验市场、证券身份、报告类型及可用内容。缺失记录不可回退到同股最新记录或 `query_id`。
- 从报告投影有限字段供模型使用，包括报告标识、生成时间、分析摘要、主要结论、风险和策略点位。可用时加入报告当时的价格、涨跌幅和市场结构。保留零值，按既有上下文预算截取并标记。以历史资料传递，范围限于所需字段，排除原始上下文快照、运行诊断和敏感配置。
- 接入 `api/v1/endpoints/agent.py` 的共用请求准备路径。服务端处理首条不带代码的指代式问题时，使用校验通过的报告确定主对象。显式切股、比较、澄清及跨市场同码走现有判定。需要引用却无法验证时，在接受用户轮次前返回可恢复错误，使用统一的对外错误提示处理缺失和无权读取。
- **完成条件**　按 ID 取得同股两份报告中的指定一份。无权读取、无可用正文、跨市场同码冲突和无效 ID 均无法进入模型输入。普通问股、旧客户端和现有策略参数仍可使用。

## T2 · 接入实际模型输入与会话状态

对应 R3、R4，依赖 T1。覆盖 `src/agent/executor.py`、`src/agent/orchestrator.py` 和相关 Agent 提示词组装。当前单 Agent 已组装旧字段，多 Agent 的 `_build_context` 现有映射未包含旧分析摘要及策略点位，需要验证实际消费路径。

- 复用同一份经服务端校验的历史资料构造模型输入。流式与非流式复用准备逻辑。单 Agent 和多 Agent 中负责生成答复的模型都应收到带来源和时间的报告内容。资料独立于会话摘要和 provider trace，每轮按当前有效范围补入。
- 在 `src/services/agent_chat_session_service.py` 和 `src/storage.py` 复用接受用户轮次的事务及会话版本校验，持久化可空报告引用。只保存记录指针，读取时按记录重新校验。缺少该字段的历史会话按无引用处理。明确切换标的或接受用户的移除请求时，在同一事务中清理引用。
- 向流式 `accepted`、会话详情和非流式响应追加可选 `active_report_context`。有效引用返回记录 ID、代码、名称和生成时间。只有该轮通过范围校验并将资料送入执行准备时，才可首次建立报告引用。澄清轮次不建立引用。报告失效时，会话详情仍可读取并返回足够的状态供界面重试或清理引用。
- **完成条件**　以两份同股报告的不同止损位作标记，截获实际模型调用参数验证选中的记录。刷新、同股第二轮、切股、比较、移除、模型失败、停止接收和会话冲突均符合 R4，后续轮次的报告资料不依赖助手曾经复述过的内容。

## T3 · 完成首页跳转、来源展示和发送控制

对应 R1、R2、R4。可与 T1、T2 并行梳理，联调依赖其请求、错误和状态契约。涉及 `HomePage.tsx`、`ChatPage.tsx`、`chatFollowUp.ts`、`agentChatStore.ts` 和 `api/agent.ts`。

- 沿用首页 `recordId` 跳转与历史详情读取，使用当前已展示报告的主键初始化独立草稿。报告尚无可引用主键时提示用户等待报告保存。刷新可恢复指定报告，接受或移除后清理入口参数。保留普通股票跳转和扫描器证据入口的现有行为。
- 在输入框附近展示加载、就绪、已引用和失败状态，提供原报告链接、重试及移除操作。沿用项目 [`DESIGN.md`](../../DESIGN.md)、问股组件和文案国际化方式。服务端接受前展示草稿状态，接受后以返回的会话状态为准。
- 在共用发送处理处拦截尚未校验的附带报告草稿，覆盖按钮、回车与快捷入口。校验失败保留输入。报告读取及流式回调都绑定到对应草稿、会话和报告 ID，离开或切换时使旧结果失效。区分「尚未接受」与「已接受后模型失败」，避免重复创建会话或丢失草稿。
- **完成条件**　覆盖慢请求、加载失败后重试、报告被删、主动移除、快速切换 A/B、刷新与原报告回跳。桌面与移动端均能看到来源和状态，页面打开时不自动发问。

## T4 · 回归验证与交付

依赖 T1–T3。先更新 `HomePage.test.tsx`、`ChatPage.test.tsx` 和 `chatFollowUp.test.ts` 的既有覆盖，把「加载中可发送」改为验证所有发送入口受控。扩展 `test_agent_chat_api.py`、`test_agent_chat_session_service.py`、`test_agent_active_stock_integration.py`，并使用现有单 Agent、多 Agent 用例校验最终模型输入。

- 后端运行 `./scripts/ci_gate.sh`。在 `apps/dsa-web/` 执行 `npm ci`、`npm test`、`npm run lint` 和 `npm run build`。检查旧会话数据、旧客户端解析可选字段，以及 Desktop 所用 Web 构建产物。
- 用同一标的两份历史报告手动验收首页刚完成分析、旧报告追问、刷新恢复和切股。PR 附桌面和移动端截图，至少覆盖成功引用和加载失败。记录线上登录与真实模型联调是否完成。
- 更新 `docs/full-guide.md`、`docs/full-guide_EN.md`、`docs/agent-stream-events.md` 和 `docs/CHANGELOG.md` 的 `[Unreleased]` 扁平条目。用户可见说明覆盖报告来源、失败恢复及会话恢复，接口文档覆盖可选字段与接受时点。
- 回滚时恢复前一版 Web 与 API，保留历史报告和聊天记录。若采用会话表新增可空列，验证旧版可读取扩展后的数据库，保留该列供后续恢复，避免回滚时改写已有会话。
