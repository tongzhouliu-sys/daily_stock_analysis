# 行情数据源多源降级需求文档

**文档版本**：v1.0  
**用途**：交付开发人员直接实现  
**第一性原则**：任何单一数据源的失效（限流、改版、协议退役、IP 封锁、服务停运），不得导致行情获取功能整体不可用。所有通道必须可替换、可验证、有明确降级路径。


## 1. 范围与约束

### 1.1 必须实现

- **交易日历**：运行时零网络依赖，完全离线可用。
- **实时快照**：当前价格、OHLC、成交量。
- **日 K 线**：日线 OHLCV，支持指定日期区间或最近 N 条。
- **分钟 K 线**：至少覆盖 1/5/15/30/60 分钟。
- **多源自动降级**：按本文档指定的优先级顺序逐源尝试，单源失败不阻断整体。
- **北交所边界处理**：明确哪些源支持北交所、哪些不支持，不支持时如何降级或告警。
- **频率合规**：对每个源施加硬性请求间隔/配额，避免因“假失效”（403/429）触发误降级。
- **可观测性**：记录每次请求实际命中的源、延迟、失败原因。

### 1.2 明确不做

- 不搭建本地全市场数据湖（Parquet/DuckDB 批量沉淀）。
- 不接入付费全市场批量行情服务。
- 不实现 WebSocket 长连接（仅 REST 轮询）。
- 不保证分钟线在所有极端场景下有免注册兜底（见 §6.3）。
- **不将 `mootdx` 纳入自动降级链**。通达信服务器自 2026-09/10 起已不再响应 `mootdx` 所实现的客户端协议，该源已从默认回退链退役。现有代码中如有 `mootdx` 引用，应标记为废弃并从自动链路移除。


## 2. 数据源池

### 2.1 免注册源（默认主路径）

| 编号 | 源名称 | 调用方式 | 覆盖范围 | 频率硬限制 | 北交所 | 数据口径 |
|---|---|---|---|---|---|---|
| **S1** | 腾讯实时快照 | `https://qt.gtimg.cn/q={code}` | A 股实时快照、ETF | **请求间隔 ≥ 100ms**；无明确 SLA，高频封 IP | 支持（老代码数据较全） | 实时 |
| **S2** | 腾讯 K 线 | `https://web.ifzq.gtimg.cn/appstock/app/fqkline/get`（日线/周/月）；`.../kline/mkline`（分钟） | 沪深个股日/周/月及 1/5/15/30/60 分钟 | 单次返回上限 **500 根**，分页上限约 12 页（≈6000 根）；连续 5000+ 次后返回空，降速可恢复，非永久封禁 | **不支持**，遇北交所代码会报错 | 日线及以上**前复权**（`fqkline`）；分钟线不复权 |
| **S3** | 新浪实时快照 | `https://hq.sinajs.cn/list={code}` | A 股实时快照、指数 | **单 IP 日请求 ≤ 1500 次**（留 30% 余量，实际控制在 1050 次/日以内）；并发 ≤ 5 QPS；需携带 `Referer` 和 `User-Agent` | 需实测确认；研报类接口支持 `bj` 前缀 | 实时（可能有 15–180 秒延迟） |
| **S4** | ashareapi | `pip install "ashareapi[pandas]"`；`AShareAPI().quote(code)` / `.kline(code, period, count)` | 实时快照（`quote`）、日/周/月/季/年及分钟 K 线（`kline`） | 免费端点无需 Key；匿名额度有限，429 时需退避 | 需实测；`kline` 支持日线及以上，分钟线付费 | 日线及以上**前复权**（服务端固定）；分钟线不复权 |
| **S5** | zzshare | `pip install zzshare`；`DataApi(token=optional)`；`api.daily()` / `api.stk_mins()` / `api.rt_k()` | 日线、分钟线、实时快照；行情覆盖 2005 年至今 | 匿名使用频率较低；可选免费 Token 提高频率；单只单次最多 1000 条，需用 `offset` 分页 | `stock_basic` 含 `BJ` 交易所；K 线接口需实测北交所 | 日线、分钟线均支持 |
| **S6** | ApocData | `BASE="https://www.apocdata.com/api/blade-dataplatform/open/data"`；`GET /quote?symbol=X` | 实时快照、行情等 45+ 端点 | 免费体验额度匿名可用；注册提高额度 | 需实测 | 实时 |

### 2.2 注册制源（可选，提高冗余度；你完成注册后填入环境变量即自动纳入）

| 编号 | 源名称 | 注册要求 | 免费额度 | 覆盖范围 | 频率硬限制 | 适用链路 |
|---|---|---|---|---|---|---|
| **S7** | Tushare | 注册获取 **120 积分** | 0 元/年 | **仅不复权日线** | **50 次/分钟，8,000 次/日** | 日 K 线备份（仅当不复权口径可接受时） |
| **S8** | iTick | 注册获取免费 Token | REST **5 次/分钟**；WebSocket 1 连接 / 3 订阅 | A 股实时、日/分钟 K 线 | 极低频，仅适合少量标的兜底 | 实时快照的最后低频防线 |

> **S7 的使用约束**：Tushare 120 积分档**只有不复权日线**。如果策略依赖前复权日线，**不得将 S7 作为主日线源**，仅可在不复权口径可接受的场景下作为校验或备份使用。

### 2.3 历史数据源（不参与实时/日线自动降级链）

**Baostock**：仅用于**历史日线/分钟线的本地缓存填充**。免费、无需注册，服务器独立于腾讯/新浪/东财链路。使用约束：**每日 ≤ 50,000 次，单连接串行，不支持并发**。以“一次拉取、本地复用”的模式使用，不进入实时降级链。


## 3. 统一路由层（必须自建，不依赖 `stockdata-hub` 默认链）

### 3.1 为什么必须自建

`stockdata-hub` 的默认 provider 优先级中 **`mootdx` 仍被列在第 1 位**，而该源已于 2026-10 退役。依赖其默认链将导致每次请求先等待一个已失效的源超时，违背“系统必须能跑”的第一性原则。因此，路由层必须由本项目自行实现，直接调用 §2 中各源的公开接口或 SDK。

### 3.2 接口契约

路由层对外暴露一个统一的 `MarketDataRouter` 类，至少提供以下方法：

```python
class MarketDataRouter:

    def get_calendar(self, start: str, end: str) -> list[str]:
        """返回区间内交易日列表。离线实现，零网络。"""

    def get_realtime(self, codes: list[str]) -> dict[str, dict | None]:
        """批量实时快照。返回 {code: {open,high,low,close,volume,ts} 或 None}。
        按 §5.1 降级链逐源尝试；单只标的全部源失败时该 code 对应 None，不抛异常。"""

    def get_daily(self, code: str, start: str | None, end: str | None,
                  count: int | None) -> pd.DataFrame | None:
        """单只标的日线。start/end 与 count 二选一。
        按 §5.2 降级链；全部失败返回 None。"""

    def get_minute(self, code: str, freq: str, count: int) -> pd.DataFrame | None:
        """分钟线。freq ∈ {'1min','5min','15min','30min','60min'}。
        按 §5.3 降级链；全部失败返回 None。"""
```

**统一返回列**（所有 DataFrame 必须至少包含）：

```
date (str, YYYY-MM-DD 或 YYYY-MM-DD HH:MM:SS), open, high, low, close, volume, amount(可选)
```

`volume` 统一为“手”，`amount` 统一为“元”（若源返回万元，须换算）。

### 3.3 路由层内部必须记录的结构

每次 `get_*` 调用后，路由层必须能返回本次调用的元信息：

```python
{
    "code": "600519",
    "data_type": "realtime|daily|minute",
    "provider_hit": "S1_tencent|S2_tencent_kline|...|ALL_FAILED",
    "attempts": [
        {"provider": "S1_tencent", "success": False, "latency_ms": 120, "reason": "timeout"},
        {"provider": "S3_sina", "success": True, "latency_ms": 340, "reason": None},
    ],
    "success": True
}
```


## 4. 交易日历：离线实现（R1）

**必须使用 `tj-calendar`**，运行时零网络请求。

```bash
pip install tj-calendar
```

覆盖范围：1990-12-19 至 **2035-12-31**，支持沪深 A 股（`SSE`/`SZSE`）和北交所（`BSE`，自 2021-11-15 起）。超出市场覆盖范围时抛出 `CalendarRangeError`，**不得静默返回错误结果**。

```python
from tj_calendar import is_trade_day, next_trade_day, trade_days_between

is_trade_day("2026-11-09")                    # True / False
next_trade_day("2025-09-30")                  # "2025-10-09"
trade_days_between("2026-11-01", "2026-11-30") # ["2026-11-02", ...]
```

**验收**：断网环境下上述三个函数正常返回；`is_trade_day("2025-10-01")` 返回 `False`；北交所 2021-11-15 之前的日期抛出 `CalendarRangeError`。


## 5. 三条独立降级链

### 5.1 实时快照降级链

```
S1 腾讯实时快照 (qt.gtimg.cn)
    ↓ 失败 / 频率受限
S3 新浪实时快照 (hq.sinajs.cn)
    ↓ 失败
S4 ashareapi quote
    ↓ 失败
S5 zzshare rt_k
    ↓ 失败
S6 ApocData quote
    ↓ 失败
S8 iTick (仅在已注册且 Token 已配置时尝试；5次/分钟)
    ↓ 全部失败
该标的本次实时快照返回 None，记录 ALL_FAILED，批次继续
```

**频率硬约束**：S1 请求间隔 ≥ 100ms；S3 单 IP 日请求硬上限 1050 次（预留 30% 余量），并发 ≤ 5 QPS；S8 ≤ 5 次/分钟。**禁止在实时链路上使用 S7（Tushare）**。

### 5.2 日 K 线降级链

```
S2 腾讯 K 线 (web.ifzq.gtimg.cn)
    ↓ 失败 / 返回空
S4 ashareapi kline
    ↓ 失败
S5 zzshare daily
    ↓ 失败
S7 Tushare daily (仅在已注册且 Token 已配置、且不复权口径可接受时尝试；50次/分钟)
    ↓ 失败
S6 ApocData (若其接口覆盖日线；否则跳过)
    ↓ 失败
Baostock (仅作为历史日线兜底；单次请求，不轮询)
    ↓ 全部失败
该标的本次日线返回 None，记录 ALL_FAILED，批次继续
```

**北交所边界（必须实现）**：S2 腾讯 K 线**不支持北交所**，遇 `bj`/`920` 开头代码会报错或返回空。路由层在检测到北交所代码时，**直接跳过 S2**，从 S4 或 S5 开始尝试。若 S4/S5 也不支持或失败，记录告警并按后续源继续。

### 5.3 分钟 K 线降级链

```
S5 zzshare stk_mins
    ↓ 失败
S2 腾讯分钟 K 线 (kline/mkline)
    ↓ 失败（北交所跳过 S2，同 §5.2）
S4 ashareapi kline(period='m1'...'m60')  (付费端点，仅在已配置 Key 时尝试)
    ↓ 失败
S8 iTick 分钟线 (仅在已注册且 Token 已配置时尝试；5次/分钟)
    ↓ 全部失败
该标的本次分钟线返回 None，记录 ALL_FAILED
```

**必须接受的事实**：分钟线是免费源覆盖最薄弱的部分。**不要求分钟线链路在所有场景下都有免注册兜底**。如果策略严重依赖分钟线，S5 应作为主源，并接受极端情况下分钟线不可用。


## 6. 频率控制与重试（强制）

### 6.1 各源硬约束汇总（实现时作为常量写入代码）

| 源 | 最小请求间隔 | 日请求上限 | 其他 |
|---|---|---|---|
| S1 腾讯实时 | **≥ 100ms** | 无明确值，高频封 IP | 批量查询用逗号拼接，减少请求数 |
| S2 腾讯 K 线 | 与 S1 共享腾讯域，建议 ≥ 200ms | 无明确值 | 单次 ≤ 500 根；连续 5000+ 后降速 |
| S3 新浪 | **≥ 1s**（实现为 1 QPS） | **≤ 1050 次/日**（硬编码） | 必须带 `Referer` 和 `User-Agent` |
| S4 ashareapi | 遇 429 退避 ≥ 2s，连续 3 次 429 则本批次跳过该源 | 以实际 429 响应为准 | 匿名额度有限，不适合大批量 |
| S5 zzshare | 匿名 ≥ 1s；配置 Token 后可适当降低间隔 | 以实际响应为准 | 分页用 `offset` |
| S7 Tushare | **≤ 50 次/分钟**（即 ≥ 1200ms/次） | **≤ 8000 次/日** | 超限进入黑名单 |
| S8 iTick | **≤ 5 次/分钟**（即 ≥ 12s/次） | 以免费套餐为准 | 仅用于少量标的兜底 |

### 6.2 重试规则

- 对**网络超时**和**5xx**：同一源内最多重试 **1 次**，间隔 1s；仍失败则进入下一源。
- 对 **403/429/401**：**不重试**，立即进入下一源，并记录该源的退避时间。
- 对**返回空但 HTTP 200**：视为**软失败**，进入下一源，但记录 `reason="empty_response"`，便于后续判断是“真无数据”还是“源端限流”。

### 6.3 降级链的“软失败”判定

以下情况均触发降级，不应视为“标的无数据”：

- HTTP 非 200；
- 返回体为空字符串或 `null`；
- 返回的 DataFrame 行数为 0；
- 返回字段缺失关键列（`open/high/low/close/volume` 任一缺失）；
- 解析异常（字段格式变化）。


## 7. 北交所特殊处理（强制）

### 7.1 代码识别

北交所代码规则：`8xxxxx`、`4xxxxx`、`920xxx`（新代码段）。路由层必须在入口处识别并标记 `is_bse=True`。

### 7.2 各链路行为

| 链路 | 行为 |
|---|---|
| **实时快照** | S1 腾讯实时快照**支持北交所**（老代码数据较全），S3 新浪需实测；路由层可正常按 §5.1 降级。 |
| **日 K 线** | **S2 腾讯 K 线不支持北交所，必须跳过**。从 S4 ashareapi 开始尝试；若 S4 不支持，尝试 S5 zzshare；仍失败则记录告警，该标的日线返回 None。**不得让北交所代码进入 S2 导致异常中断批次**。 |
| **分钟 K 线** | 同样**跳过 S2**。从 S5 zzshare 开始；若失败，S4 分钟线为付费端点（未配置 Key 则跳过）；最终失败记录告警。 |

### 7.3 验收

构造一个包含至少 1 只北交所代码和 2 只沪深代码的批次，执行日线获取：

- 沪深标的从 S2 正常返回；
- 北交所标的**不触发 S2**（日志中不得出现北交所代码请求 S2 的记录）；
- 批次完整结束，北交所标的若全部源失败，记录 `ALL_FAILED` 告警，不影响沪深标的。


## 8. 可观测性（强制）

每次 `get_realtime` / `get_daily` / `get_minute` 调用后，**必须**输出一条结构化日志，至少包含：

```
timestamp, code, data_type, provider_hit, success, latency_ms, attempts(JSON)
```

**监控规则**：

- 如果某数据类型的 `provider_hit` 中 **主源（S1/S2/S5）占比持续低于 50%**，说明主源受限或失效，需要提前介入；
- 如果出现 **`ALL_FAILED`**，必须记录 `attempts` 的完整内容（每个源的失败原因），用于判断是“所有源同时不可用”还是“频率控制误伤”。

**实现建议**：日志写入文件（`market_data_router.log`），字段用 JSON 行格式，便于后续用 `grep`/`jq` 分析。

## 10. 验证清单（交付前必须逐项通过）

| 编号 | 验证项 | 通过标准 |
|---|---|---|
| **V1** | 单源逐项连通性 | 对 S1、S2、S3、S4、S5、S6 各执行一次最小请求（1 只沪深标的、1 条数据），**至少 4 个源**返回有效数据。记录每个源的延迟。 |
| **V2** | 实时降级链模拟失效 | 手动禁用 S1（如将 URL 指向不可达地址），确认 S3 被自动触发并返回数据；日志中 `provider_hit` 为 S3。 |
| **V3** | 日线降级链模拟失效 | 手动禁用 S2，确认 S4 或 S5 被自动触发并返回日线数据；日志中 `provider_hit` 为对应备源。 |
| **V4** | 频率合规 | 连续请求 10 只标的的日线，不触发 HTTP 403/429 或连接重置；S3 的日请求计数在 1050 以内（本地计数器验证）。 |
| **V5** | 北交所边界 | 按 §7.3 构造批次，验证北交所代码不进入 S2，批次不中断。 |
| **V6** | 批次容错 | 构造包含 1 只无效代码（如 `999999`）和 2 只有效代码的批次，执行日线获取；无效代码的 `ALL_FAILED` 被记录，有效代码正常返回。 |
| **V7** | 断网日历 | 断开网络，执行 `get_calendar("2026-11-01", "2026-11-30")`，正常返回交易日列表。 |
| **V8** | 可观测性 | 检查日志文件，确认每次调用都有 `provider_hit`、`success`、`latency_ms`、`attempts` 字段。 |

**V1–V8 全部通过，方可视为满足“系统能正常运行”的第一性原则。**
