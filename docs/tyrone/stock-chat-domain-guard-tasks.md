## 2. 统一处理顺序

```text
接收用户请求
  → 既有认证、输入与会话归属校验
  → 读取必要的有效会话背景
  → 统一领域判断
      allow        → 原有对象澄清／首次问卷／研究流程
      redirect     → 定位提醒＋其他平台建议，结束本轮
      clarify      → 定位提醒＋请求投资关联，等待用户补充
      direct_reply → 简短社交回应，不开启研究
```

系统使用帮助使用 `allow`，但限制在系统帮助语义内，不能凭帮助分类启动无关市场研究。混合问题在可分离时使用 `allow` 并携带范围提醒与投资子请求；不可分离时使用 `clarify`。

领域判断必须发生在可能因无关文本而改变标的的对象解析、研究规划、行情与新闻调用之前。已有流程如果把读快照、对象解析和写入绑定在一起，应只拆出完成此顺序所需的最小部分，不重构整套会话系统。

## 3. 建议内部契约

新增一个集中管理的领域决策结构，优先放在 `src/schemas/`；共享服务建议为 `src/services/agent_domain_guard_service.py`。这些路径是拟新增位置，不代表已有实现。

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `action` | 枚举 | `allow`／`redirect`／`clarify`／`direct_reply` |
| `reason_code` | 枚举 | `investment`／`mixed`／`system_help`／`social`／`off_topic`／`ambiguous`／`check_unavailable` |
| `message` | 字符串或空 | 由受控模板生成的用户可见提醒；普通投资允许时可为空 |
| `allowed_request` | 字符串或空 | 仅可分离的混合问题使用，保留原始投资要求；不能增加标的或条件 |
| `policy_version` | 字符串 | 判断规则版本，便于回归与诊断 |

服务端校验动作与原因组合，拒绝未知枚举；`check_unavailable` 对应 `clarify`，不得伪装为 `off_topic`。模型只提供受校验的分类和必要片段，不决定回复模板或调用工具。

正式聊天响应拟追加可选 `domain_guard` 元数据，保留现有 `content`、`success` 等字段。纯提醒是成功完成的一次对话回应，`success=true`，不伪装成服务器错误；研究没有运行时 `total_steps=0`。如调用过分类模型，其消耗不能声称为零研究外消耗。

SSE（服务端事件流）沿用 `accepted` → `done`；提醒正文放在 `done.content`，附可选 `domain_guard`。不新增客户端必须认识的终止事件，不伪造行情或研究阶段。消息保存失败、会话冲突等真实错误沿用既有错误契约，不转换为领域提醒。

首次问卷是预检，和正式发送分开处理：

- 通过则沿用现有问卷响应。
- 需要提醒、补充或社交短答时，不创建空的假问卷；返回 HTTP 422，`detail.error=domain_scope_required`，附 `detail.message` 和 `detail.domain_guard`。前端识别该业务结果，停止问卷并展示正文，不显示通用网络错误。
- 预检不保存正式用户／助手消息；前端可临时展示。用户提交正式聊天时重新验证，使用同一问题和会话版本的可信结果避免重复模型调用，最终只保存一组正式消息。
- 旧客户端仍可直接正式聊天，得到标准 `content` 提醒。领域结果不能由客户端声称“已通过”来覆盖。

研究 API 沿用其 `content` 和 `sources` 契约，纯提醒的 `sources=[]`，不生成“研究报告”来源。Bot 直接显示提醒，不加“深度研究完成”标题。具体新增可选字段在 T2 中同步类型和契约测试。

### T0 · 确认入口与验收基线

- 读取上述入口及调用关系，记录哪些路径会在正式研究前调用对象解析、上下文压缩或模型；检查单／多 Agent 是否真正共用服务。
- 以需求 R8 建立至少 60 条固定样本，记录输入、有效上下文、期望动作、允许研究范围。人工标注的期望不得由待测分类器生成。
- 记录当前响应耗时，拟定一次模型补判的独立超时上限，使其受现有总请求预算约束。超时值写入测试和文档；若新增配置，同步 `.env.example`、配置注册与专题说明。
- 检查首次引导和股票消歧的现行顺序；现有文档与运行代码不一致时以代码为准，不把其他未验收任务视为已完成。

完成标准：每个自由文本入口都有明确接入位置与测试，投资知识与闲聊不再共用拦截标签。

### T1 · 实现共享判断与受控提示

- 服务输入为原始问题、必要的有效上下文和已有配置；输出第 3 节的决策结构，不直接执行研究或写会话。
- 规则识别明确投资、系统帮助、社交、无关与混合意图；关键词只能辅助，覆盖同名词、否定、旧背景与当前意图冲突。
- 规则不能判断时，最多一次无工具模型补判；使用现有模型路由，不指定新的硬编码模型或供应商，不做多轮自我辩论。
- 区分超时、不可用、非法枚举与不完整输出；返回受控的 `check_unavailable`，日志保留原因而非用户全文。
- 对混合请求只保留可验证的投资子请求，不能丢失“只看长期”“不要给买卖建议”等限制。无法可靠提取则请求补充。
- 受控模板覆盖中英文；系统帮助只回答已有能力，社交短答不进入研究。补充背景规则按原问题关联记录，避免反复询问同一关联。

完成标准：固定用例与故障注入通过；服务可独立测试，模型输出不能触发工具或改写规则。

### T2 · 接入聊天、问卷和会话保存

- 在共享的准备层调用领域服务，覆盖同步与 SSE；不要分别在两个路由里复制关键词判断。
- 对纯提醒复用现有接受轮次和结果保存机制，跳过研究执行器及答案精编，保证先接受、后写入终态。检查现有股票澄清保存逻辑是否适用，不直接复用会改变标的的分支。
- 提醒轮次保留已确认标的、报告来源和分析背景。只修改当前消息、必要的请求状态和会话版本；不能将无关文本注入下一轮分析背景。
- 补充背景时仅组合被关联的原问题和新补充；新问题或切换会话时不携带旧的待澄清请求。
- 首次引导在领域判断之后生成；按第 3 节处理业务 422，已确认／跳过问卷仍不能绕过正式请求校验。
- 同请求重放、用户主动重试、断流恢复分别沿用现有请求身份规则。复用判定至少绑定问题、会话代次、背景版本、规则版本，不能把旧允许结果套到新问题。
- 对消息元数据采用向后兼容的可选扩展；未包含元数据的历史记录按普通正文读取，不重新调用分类模型。

完成标准：直接调用 API、跳过问卷、刷新恢复和会话冲突均符合需求；纯提醒没有研究工具事件，没有残留运行状态。

### T3 · 接入 Bot 和深度研究入口

- Bot `/chat` 及独立执行器调用同一服务，不能只给 Web 加限制。检查 `AgentExecutor.chat` 和多 Agent 聊天路径的共享接入或受控转发。
- API/Bot `/research` 对用户原始问题检查，股票代码和系统拼接的 `[Stock: ...]` 不能掩盖无关意图；只给代码的原有股票研究命令仍正常工作。
- 在启动深研后台任务、建立研究计划和调用工具前返回提醒。内部子问题及定时分析不重复执行用户领域门禁。
- Bot 输出正文，不触发额外主动通知；无关提醒不生成虚假研究标题、来源或完成统计。

完成标准：同一核心用例在 Web、Bot 和研究 API 的决策一致；原有结构化分析与有效研究场景回归通过。

### T4 · 客户端呈现与恢复

- 扩展 API 和 store 类型，兼容缺少 `domain_guard` 的旧响应；业务 422 与网络故障分别处理。
- 提醒使用现有聊天正文，遵循根目录 `DESIGN.md`；不引入新主题或全屏拦截页面。
- `redirect`、`clarify`、`direct_reply` 均正确结束本轮加载。混合请求只在最终回答保留一份范围提醒，流式内容、最终内容与历史内容一致。
- 如提供“补充投资背景”“换个投资问题”操作，保持键盘可达和可编辑；点击、倒计时、刷新都不自动提交。
- 覆盖新建、追问、快捷提问、报告追问、停止接收、历史恢复与导出；迟到事件按既有请求身份隔离。
- 同步已有界面语言的提醒文案；手机、深浅色和共用 Web 的桌面端均能读完提醒。

完成标准：页面不显示虚假研究进度，不强制用户新建会话；前端关闭校验时服务端仍正确控制流程。

### T5 · 集成验证与交付

验证重点是“实际入口是否阻止了无关研究”，不能只测模板字符串或把共享判断全 mock 掉。

- 单元测试：分类、上下文、混合请求限制保留、受控模板、模型结果校验与超时降级。
- 后端集成：使用临时数据库，从真实 API／Bot 入口发起请求；只替换外部模型／行情边界，断言研究执行器和工具调用次数为 0，消息保存、状态和标的正确。
- 对允许的投资问题增加反向对照，证明进入现有分析链路；使用 `AGENT_ARCH` 的现有单／多模式覆盖相关分支。
- 前端：领域提醒、业务 422、SSE 终态、旧响应兼容、历史恢复、会话切换、补充背景和导出测试。
- 在线验证：若启用模型补判，使用已配置模型跑固定样本并记录版本、耗时和错误；无法在线验证时单列缺口，不宣称模型准确率已达标。

## 5. 完成定义、风险与回滚

- R1–R8 均有可复核证据；固定强制场景通过，至少 60 条样本有结果，模型参与时至少重复 3 次。模型随机性和未验证路径写入交付说明。
- API、新旧客户端、Bot、深研与单／多 Agent 语义一致。提醒后可继续合法问题，历史／报告上下文不被覆盖。
- `docs/CHANGELOG.md` 用 `[新功能]` 或 `[改进]` 记录实际实现，更新相关专题文档；本次 `[文档]` 条目不能充当上线记录。
- 提交受影响页面截图，覆盖明确无关、待补充、混合问题和移动端；一次性截图只放外部验收产物或 PR 附件。
- 本任务最大风险是误拦合法投资追问、模型补判延迟与多个入口遗漏。回归测试须验证这些反例，不能用 CI 通过替代语义验收。
- 回滚采用撤回本功能代码或恢复上一可用发布；数据库扩展必须兼容旧读写，不删除历史对话，不改现有主键。无必要不新增开关；若确需开关，应统一所有入口并同步配置文档。
- 本次交付为中文内部任务书，无对应英文版本；实施时现有用户界面多语言需要同步。文档自身回滚只需移除本次新增两份文档和对应 changelog 条目，不影响运行服务。
